## 5. 去重方法（五条规则）

1. **统一唯一键**：按 PMID → DOI → 官方 URL → 会议摘要编号 的优先级取唯一标识；同一标识只保留主卡。
2. **一稿多形态合并**：同一研究的会议摘要 + 预印本 + 正式论文 → 以**正式论文为主卡**，其余作为「关联条目」记录在备注，不单独建卡。
3. **指南新旧版本**：以**最新版为主卡**，旧版作为「版本历史」条目（记录更新日期与主要变化，服务"版本演进"查询）。
4. **中文解读 vs 原文**：公众号解读（如雨露肝霖）**不单独建卡**，只写入主卡的「二次解读链接」字段；一条解读若对应多篇原文，可多卡引用。
5. **标题相似度复核**：录入时对标题做相似度筛查（编辑距离），疑似重复（同一人群+同一治疗+相近标题）自动列出人工复核，复核不过不入库。

## 6. 证据等级与关注优先级（双维独立，绝不合并）

### 证据等级（研究设计定，中国研究不自动升级）

| 等级 | 判定标准 | 典型类型 |
|---|---|---|
| **A** | 指南、共识、RCT、III 期、高质量系统综述/Meta 分析 | WHO/国家卫健委文件、中华医学会/EASL/AASLD/APASL 指南、已发表 III 期 |
| **B** | II 期、全国性/多中心队列、大样本前瞻、高质量真实世界研究、高质量卫生经济学 | 珠峰/星光/容愈/扬帆/甘泰/终结等项目的正式发表版本 |
| **C** | 单中心观察、回顾性、探索性生物标志物、预测模型内部验证 | 单中心回顾队列 |
| **D** | 病例报告、机制/动物、专家观点、缺验证内容 | **原则上排除**；联盟建设类政策解读可例外并显式标注 |

### 关注优先级（对策略/联盟/路径的影响度定）

| 等级 | 判定标准 |
|---|---|
| **P0** | 直接影响全国策略、指南、联盟建设或临床路径，需要立即关注 |
| **P1** | 对治疗选择、优势人群、功能性治愈、HCC 预防或患者管理具有较高价值 |
| **P2** | 有一定补充价值，暂不足以改变实践 |
| **P3** | 价值有限或质量低，仅作资料保留 |

> 二者可自由组合（如 A/P0、B/P1、C/P2）。同一篇文献两个维度分别打标，检索时可分别筛选。

## 7. 检索与溯源原则

1. 优先原始论文、官方指南、正式政策、学会文件。
2. **线索→原文闭环**：从肝斗士库检索线索（关键词覆盖六大专题）→ 提取关键结论 → 联网（PubMed/期刊官网/指南官网/会议官网）溯源到原文，核对 PMID/DOI → 才允许建卡。
3. 雨露肝霖等公众号仅作线索与解读，**不替代原始证据**；其引用的原始论文、指南、会议摘要必须找到 PMID/DOI/官方页面。
4. 每项结论必须可追溯至具体文献或政策。
5. 不把相关性描述成因果关系；不把动物/体外结果外推临床；中国证据不自动升级。
6. 数值规范：HBsAg/HBV DNA 下降必须带**时间节点 + 单位**（如"24 周下降 ≥1 log10 IU/mL"），禁止"明显下降"这类模糊表述；所有数字与原文核对，无法确认填「待核查」。

## 9. 问答与总结层设计（追加需求）

> 目标：让知识库不仅能查，还能"基于库提问、得到带证据的总结回答"。
> 提供三个通道，按使用场景分工；全部基于同一套结构化主表与原文层，保证回答可溯源。

```
┌────────────────────────────────────────────────────────────┐
│  主库（证据层主表 + 原文层 + 专题页）                          │
├────────────────────────────────────────────────────────────┤
│  通道① WorkBuddy 内置问答（即时可用，零开发）                  │
│  · 豆豆在对话中提问 → 检索主表 + ima 原文层 → 总结回答         │
│  · 回答规范：结论 → 证据（文献+PMID/DOI+链接）→ 等级/优先级    │
│    → 区分共识/争议/证据缺口，不编造                           │
├────────────────────────────────────────────────────────────┤
│  通道② 独立 HTML 问答应用（推荐开发，面向团队/外部）            │
│  · 单文件 HTML，内嵌主表 JSON + 16 个专题页摘要                │
│  · 本地检索：关键词 + 专题过滤 + 标签筛选（简化 BM25）          │
│  · 总结生成：结构化模板（结论/证据/分级/争议/行动建议）          │
│  · 可选增强：接入 Kimi/Moonshot API 做开放式总结（无 key 时     │
│    用内置模板兜底，保证离线可用）                              │
│  · 部署：本地直接打开；需要分享时用 CloudStudio 发布链接        │
├────────────────────────────────────────────────────────────┤
│  通道③ ima 原生问答（同步后自动可用）                          │
│  · 原文层按专题同步进 ima 后，成员在 ima 客户端内直接对库提问   │
│  · 适合联盟/团队内部共享使用                                  │
└────────────────────────────────────────────────────────────┘
```

**开发时间点**：通道①随建库全程可用（建卡即能问）；通道②在 S5 主表定稿后开发（S7 阶段交付）；通道③随 S9 同步完成。
